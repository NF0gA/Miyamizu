# Miyamizu

音質(時間軸の正確さ)を優先するミュージックプレイヤー(Linux 向け。Windows 版は実機未検証)。PyQt6 製。
データ伝送のジッターを減らし、音を時間的にできるだけ正しく DAC へ送ることを目的にしています(専用コア・リアルタイム優先度・ビットパーフェクト出力)。

- 動作確認環境: openSUSE Tumbleweed / KDE Plasma(Wayland) / PipeWire / Python 3.12 以降
- ライセンス: GPL-3.0-or-later(`LICENSE`)。第三者ソフトウェアは `THIRD_PARTY_NOTICES.md`
- バージョン: 1.0.0

## 特徴

- **ビットパーフェクト再生**: ALSA hw 排他出力で、素通し(音量 0dB・リサンプルなし)なら整数のまま DAC へ送ります。再生バーの表示で加工の有無を確認できます。
- **出力**: PipeWire 共有 / ALSA hw 排他 / カスタム ALSA デバイス。出力プロファイルを保存して切り替えできます。共有⇔排他の切替で、OS のミキサーを触らずにメイン機器を割り当て直します。
- **時間軸**: 再生スレッドを SCHED_FIFO(権限が無ければ rtkit)で優先化し、専用 CPU コア(SMT 兄弟も除外)へ固定。デコード・リサンプルは別プロセスで行い、共有メモリのリングで渡します。周期ジッターと xrun はテレメトリに表示します。
- **ギャップレス**: 次曲を先読みして途切れなく再生します。CUE+FLAC は 1 枚を「アルバム(フォルダ)」として扱います。
- **RAM 再生 / 事前変換**: 曲全体をデコード(+リサンプル)して RAM に置いてから再生します。再生中の処理を無くすための任意機能です。
- **リサンプル(既定 OFF)**: soxr(品質・位相・通過帯域を選択)と r8brain-free-src(遷移帯域・阻止域減衰・位相を選択)。系列内最大・2 倍・4 倍・固定レート。
- **量子化**: ビット深度を落とす時だけ TPDF ディザまたはノイズシェーピング(任意)を使い、量子化は最後の 1 回だけです。
- **アプリ音声を排他出力で再生**: ブラウザなど他アプリの音を取り込み、Miyamizu の排他出力で再生します。
- **対応形式**: flac / wav / mp3 / m4a(AAC・ALAC) / aac など(設定で取り込む拡張子を選択、無視する拡張子も指定可)。
- ライブラリ管理、プレイリスト(D&D・M3U8)、リピート/シャッフル、再生キュー、アルバムアート背景、ドックの自由配置。

## 導入と起動

必要なもの(openSUSE): `sudo zypper in python3 libasound2 libsndfile1`(PyAV・soxr は pip の wheel を使います)。アプリ音声の取り込みには `pactl` と `parec`(PipeWire の pulse 互換)が必要です。

```
./start.sh
```

`start.sh` が venv の作成 → 有効化 → 不足パッケージのみ導入 → 起動を行います。アプリメニューに登録するには `./install_desktop.sh`。

### リアルタイム優先度
権限が無いと「RT が無効」と表示されます。`./setup_realtime.sh`(rtkit 導入 + `limits.d` + audio グループ。sudo 必要、実行前に確認あり)で一括設定できます。手動の場合:

- `/etc/security/limits.d/audio.conf` に `@audio - rtprio 95` と `@audio - memlock unlimited` を書き、`sudo usermod -aG audio $USER` のうえ再ログイン
- 権限が無い場合は rtkit にフォールバックします。原因と対処はテレメトリの「RT:」行に出ます。
- CPU governor を performance に(`cpupower frequency-set -g performance`)すると周波数の揺れが減ります。専用コアは設定の「時間軸」で指定します。

## 使い方

### 基本
1. 「ファイル」または設定でライブラリのフォルダを登録すると、ツリーと曲リストに展開されます。
2. 曲をダブルクリックで再生。CUE+FLAC はツリーの 💿 が 1 枚ごとのアルバムです。
3. 再生バーでシーク・音量・リピート・シャッフル・出力プロファイルを操作します。⏏ で出力デバイスを解放します。
4. 列見出しのクリックで並べ替え(昇順→降順→元の順)。「表示 → 並び順を元に戻す」でアルバム/トラック順に戻ります。右の「再生キュー」は、これから再生される順(シャッフル/リピート反映)で、ダブルクリックでジャンプします。

### ビットパーフェクトで聴く
1. 設定 → 出力で「ALSA hw(排他)」を選び、DAC を指定します。
2. リサンプル OFF・音量 100%(排他では音量は無視されます)・ディザは既定のままにします。
3. 再生バー付近の表示が「ビットパーフェクト」になれば、素通しです(「加工あり」の場合はシグナルパスに理由が出ます)。

### 出力プロファイルとメイン機器
- 出力設定の「メイン機器」は共有・排他で共通です。
  共有へ切替: メイン機器を PipeWire の既定出力にします。
  排他へ切替: メイン機器を OS の共有側から外して専有します(カードのプロファイルを off)。
  解放(⏏)・共有へ戻す・終了: 元に戻してメイン機器を共有へ再割り当てします(異常終了しても次回起動時に復元)。
- 再生バーのプルダウンで切り替え、「再生 → 出力プロファイル」で現在の設定を名前を付けて保存/削除します。切替時は同じ位置から新しい出力で再開します。
- 相手が使用中(busy)の場合は、シンクの suspend → カードのプロファイル一時 off → 使用中プロセス名の表示、の順で対処します。再生中の他アプリを止めて良い場合だけ、設定「それでも使用中なら…」を有効にしてください。

### リサンプル
設定 → リサンプルで有効化します(既定 OFF)。エンジンは soxr / r8brain。

- **soxr**: 品質(QQ〜VHQ、32bit 精度)・位相(線形/中間/最小)・通過帯域(標準/広帯域)。libsoxr が必要です(無ければ標準設定)。
- **r8brain**: プリセット 標準(遷移帯域 2% / 207dB / 線形)・最小位相・高速(10% / 120dB)・詳細(遷移帯域 0.5〜45%、減衰 49〜218dB、位相)。「ヘッドルーム」で、変換後のインターサンプルピークによるクリップを避けるため変換前に少し下げられます(既定 0dB)。`g++` があれば初回に自動ビルドします(`./build_r8brain.sh` で事前ビルドも可)。使えなければ soxr に戻ります。
- 同レートの曲は変換しません。固定レートにすると曲間でレートが変わらず、DAC の再同期(無音・ポップ)が起きません。ソースが出力上限を超える場合は、設定に関係なく上限系列へダウンサンプルします。

### RAM 再生と事前変換
設定 → 再生。RAM 再生が ON のとき、曲リストの「RAM」列に ●(展開済み)/◐(読み込み中)を表示します。「事前変換する先読み曲数」で、次曲より先の曲も(デコード→リサンプル→量子化まで)再生前に済ませます。変換は 1 曲ずつ、再生中・次曲より低い優先度で進みます。

### アプリ音声を排他出力で再生
メニュー「再生 → アプリの音声を排他出力で再生…」で、音を出しているアプリを選ぶと、その音を専用の仮想シンクへ移して取り込み、排他出力で再生します。

- **排他出力専用**です。取り込み中は RAM 再生・リサンプルが無効になります。
- 一覧は音が出ているストリームを 🔊 とバーで上に表示します。同じアプリが複数並ぶ時は、バーが動くものを選んでください。
- 遅延は設定の「アプリ音声の遅延(目標)」(既定 40ms)。既定で自動調整し、音切れしない範囲で下げます。クロック差は連続補正(微小リサンプル)で吸収します。取り込みレートはアプリのストリームに自動で合わせます。
- 停止・終了・異常終了後はアプリの出力先を元に戻します。

### 量子化(ディザ・ノイズシェーピング)
ビット深度を落とす時(32bit/浮動小数 → 24/16bit)だけ働きます。素通しには影響しません。ノイズシェーピング(設定、既定 OFF)は量子化ノイズを高域へ寄せます。24bit 出力ではほぼ差がなく、16bit 出力で効きます。C ライブラリ(`miyamizu/nshape.c`)を使い、`cc` があれば自動でビルドします。

### 静音モード
再生メニュー/設定。状態通知を間引いて、再生スレッドへの干渉を抑えます。再生位置の表示更新は粗くなります。

### デバッグ機能
設定 → 「その他」で「デバッグ機能を有効にする」を入れると、メニューに「デバッグ」が現れます。ABX 聴き比べ(出力プロファイル A/B。X は毎回ランダムで、正解数と偶然の確率を表示)が使えます。

## Windows 版(実機未検証)

Linux 版の ALSA/PipeWire 部分を WASAPI(sounddevice 経由)に置き換えたものです。**開発環境に Windows が無いため、実機での動作は未確認です**(偽のデバイスでのビット一致、通信、ビルド手順の確認まで)。

- 起動: `start.bat`(venv 作成 → 不足パッケージのみ導入 → 起動。Python 3.12 以降が必要)。r8brain とノイズシェーピングも使う場合は、MSYS2(UCRT64 の gcc)を入れて PATH に通し、一度 `build_native.bat` を実行してください(以降は `start.bat` でそのまま使えます)。
- ビルド: `build.bat` → `dist\Miyamizu\Miyamizu.exe`(PyInstaller onedir)。r8brain とノイズシェーピングの DLL は、MinGW-w64(`g++`/`gcc`)が PATH にあればビルド時に同梱されます。無くても動きます(r8brain は選べず、ノイズシェーピングは使えません)。
- 出力方式: 「WASAPI 共有」(既定)と「ビットパーフェクト(WASAPI 排他)」。排他は、実際に開ける形式(整数 32/24/16bit)を問い合わせて変換なしで渡します。他のアプリが排他で使用中だと開けません。
- 時間軸: 再生スレッドに MMCSS(Pro Audio)と TIME_CRITICAL、タイマー分解能 1ms を設定し、専用コアは SetThreadAffinityMask で固定します(SMT 兄弟は自動で空けます)。電源プランは「高パフォーマンス」を推奨します。
- エンジンとの通信は 127.0.0.1 の TCP(起動ごとのランダムなトークンで認証)、設定は `%APPDATA%\miyamizu`、ログ・DB は `%LOCALAPPDATA%\miyamizu` です。
- 未対応: アプリ音声の取り込み(PipeWire 依存)、共有/排他のメイン機器の割り当て、PipeWire 関連の設定。ソフト音量は共有のみ有効です。
- soxr: Windows の python-soxr は位相・帯域を選べない標準設定です(位相などは r8brain エンジンで選べます)。
- 確認してほしいこと: ①排他で開けるか(サンプルレート・形式の一覧は「このデバイスを調べる」)、②再生バーの表示が「ビットパーフェクト」になるか、③曲間のレート切替、④長時間再生での途切れ(テレメトリの xrun)。不具合は診断レポートを添えて報告してください。

## 困ったとき

- **診断レポート**: ヘルプ → 診断レポートをクリップボードにコピー(設定・デバイス・RT・メトリクス・engine.log 末尾)。
- **ログ**: `~/.local/share/miyamizu/` の `engine.log` / `crash.log`(GUI) / `engine_crash.log`(エンジン)。
- **再オープン直後の無音**: ALSA/カスタム出力でデバイスを開き直した直後に流す無音(既定 300ms)。DDC/DAC のロック待ちで曲頭が欠けるのを防ぎます。
- **PipeWire のレート固定**: 設定の該当項目は `pw-metadata clock.force-rate` を使います。常時固定したい場合は `~/.config/pipewire/pipewire.conf.d/rate.conf` に `context.properties = { default.clock.allowed-rates = [ 44100 48000 88200 96000 176400 192000 ] }`。

## 構成

GUI(PyQt6) ⇄ UNIX ソケット(JSON 行) ⇄ エンジンプロセス(制御スレッド + 出力スレッド) ⇄ 準備プロセス(デコード/リサンプル/量子化。共有メモリのリングで出力スレッドへ渡す)。GUI を閉じるとエンジンも終了します。設定とライブラリ DB は `~/.config/miyamizu` / `~/.local/share/miyamizu` です(旧名 hifiplayer からは初回起動時に自動で移します)。

エンジン単体(テスト用): `python -m miyamizu.engine --socket PATH [--test-backend null|capture[:file]|capture-paced] [--no-rt]`。GUI から使う場合は環境変数 `MIYAMIZU_ENGINE_ARGS="--test-backend null"`。テストは `tests/`(`python tests/test_*.py`、`PYTHONPATH=.` が必要)。

## ビルド(実行ファイル)

Linux: `./build.sh` → `dist/Miyamizu/Miyamizu`(Windows は上の `build.bat`。PyInstaller onedir。同じ実行ファイルを `--engine` で再起動してエンジンにします)。実行ファイルの隣に `icon.png` を置くとアイコンを差し替えられます。

## 既知の制限

- 実機での音の出方・RT・排他の挙動は環境(DAC・PipeWire/WirePlumber のバージョン)に依存します。うまくいかない時は診断レポートを添えて報告してください。
- AAC のシークは約 5ms ずれる場合があります。
- 音量変更の反映は、ストリーミング時にリング長ぶん遅れます。
- MPRIS 未対応。Windows 版は実機未検証です(`docs/WINDOWS_PORT_PROMPT.md` は移植時の仕様メモ)。
